# YeneY — the UPnP layer

YeneY owns discovery, SOAP control, subscriptions and HTTP serving. The bridge
uses `upnp::SpeakerControl` and `upnp::StreamServer`; HTTP handlers receive
`upnp::StreamRequest`. HTTP/XML helpers contain no LMS, stream-generation or
transport-intent state. No SMAPI service is implemented.

## Startup and discovery

`SONOS_LMS_UPNP=yeney` and `own` (permanent alias) select YeneY. Unset also selects
YeneY. Other values log `SONOS_LMS_UPNP=<value> is no longer supported; using YeneY`
and continue. Selection is read and logged once: `UPnP layer: yeney`, adding
` (alias own)` for the alias. `--list-rooms` uses the same discovery implementation
and sends diagnostics to stderr to keep stdout machine-readable.

SSDP M-SEARCH uses 239.255.255.250:1900 and ZonePlayer:1, waits three seconds and
retries once if no valid replies arrive. `--ip` bypasses SSDP. ZoneGroupState
comes from `/ZoneGroupTopology/Control`. Room matching is exact and case-sensitive,
accepting individual names or combined group names; invisible bonded members are
excluded and ambiguous names fail. Commands and AVTransport reads target the
group coordinator; RenderingControl and topology target the selected room.
Coordinator changes move the AVTransport subscription without regrouping speakers
or changing LMS sync. Failed topology reads retain the last good snapshot.

## HTTP and wire compatibility

The server binds `0.0.0.0`, searching ports 1400 through 1409, and accepts up to
16 connections. Excess connections receive 503. Headers are limited to 16 KiB
and five seconds. The stream URL remains
`/music/squeezebox.flac?session=<process-token>&stream=<generation>`. Invalid or
missing session tokens receive an empty 404 before stream ownership is touched.

The named Server constants retain `libnoson/2.13.2` for stream responses and
`SONOS/2.13.2` for helper replies, including HEAD, for device compatibility.
Every response closes the connection. Audio uses chunked `audio/flac`; send I/O
has a 500 ms deadline. `/images/pulseaudio.png?id=2.13.2` remains the artwork URL,
with `image/png`, Content-Length and `Cache-Control: public, max-age=86400`.
The project-owned PNG and embedded header are generated by
`scripts/make-icon.py` using the Python standard library. Builds use committed
bytes. The local-file diagnostic was removed; only stream, icon and event routes
are served.

## Metadata and SOAP

`streamDidl()` retains an `http://` CurrentURI for FLAC with
`x-rincon-mp3radio:*:audio/flac:*` protocolInfo. Device probes on 28 September 2026
using `scripts/stream-probe.py` showed why: the URI scheme selects the client.
The normal HTTP client plays FLAC without requesting ICY. Changing CurrentURI to
`x-rincon-mp3radio://` selects the radio client, which requests `Icy-MetaData: 1`
with a User-Agent ending in `Nullsoft Winamp3` for both MP3 and FLAC. In that
client FLAC buffers and reconnects; MP3 plays and ICY StreamTitle reaches
`r:streamContent`, but the current Sonos app still displays only the title.
Keep the HTTP URI and radio protocolInfo combination unchanged.
The item has no id, parentID or restricted attributes. Class precedes title;
namespace order and the space before the closing DIDL opening-tag `>` are pinned
by fixtures. XML escapes `& < > "` and leaves apostrophes literal. Empty artist,
album and artwork fields are omitted; streamContent remains an explicit element.

`SONOS_LMS_TITLE_FORMAT=artist-title|title` defaults to `artist-title`. With an
artist, dc:title becomes `Artist - Title`; without one it remains `Title`. The
`title` setting preserves the unformatted track title. Invalid values warn and
select the default; the setting is read/logged once at startup. The controller
caches the actual serialized title for status and fallback matching; bridge logs
use the same formatter. Radio text still uses the original title:
`SONOS_LMS_STREAM_CONTENT=structured|plain|off` is unchanged. Creator and album
remain available to other controllers.

On 28 September 2026, Study's Sonos app displayed only dc:title for radio-type
items, ignoring creator, album, structured/plain streamContent, radioShowMd and
musicTrack/audioBroadcast class changes. Prefixing dc:title with the artist
worked. See README for the owner-run `scripts/meta-variant.py` procedure.

All seven AVTransport actions use `/MediaRenderer/AVTransport/Control`,
InstanceID 0, and `urn:schemas-upnp-org:service:AVTransport:1`. Play, Pause and Stop
retain Speed=1. SetAVTransportURI must succeed before Play. Content-Type remains
`text/xml`. GetMediaInfo supplies CurrentURI independently of TrackURI. Faults
log action, errorCode and errorDescription, including HTTP 500 responses.
`tests/fixtures/radio-set-uri.xml` and `radio-didl.xml` pin the established wire
bytes; title-format and stream-content fixtures cover both formats, omitted
fields, Unicode and XML escaping.

## Events, polling and deadlines

GENA `/avt`, `/rc` and `/zgt` share the stream listener. Subscriptions request
300 seconds, renew halfway through their grant, and retry after one second then
every five seconds. Renewal checks the local address towards the speaker; a
change recreates the subscription. Subscription I/O has a two-second deadline;
unsubscribe and SID-publication races are bounded at 500 ms. First notification
bodies after subscription/renewal are logged on one line, limited to 4 KB.

With all subscriptions active, position is polled at most once per second while
PLAYING/TRANSITIONING, plus a 30-second transport sanity check. Missing services
individually fall back to polling. `SONOS_LMS_YENEY_POLL=legacy` restores the older
500 ms polling schedule; `events` is the default. Delayed reads cannot overwrite
fields updated by a later event. HTTP workers read cached snapshots and never
perform SOAP I/O for transport status or display volume.

| Action | Exchange deadline |
| --- | --- |
| Play, SetAVTransportURI, Stop, Pause | 20 seconds |
| GetTransportInfo, GetPositionInfo, GetMediaInfo, GetVolume, GetZoneGroupState | 5 seconds |

The transport deadline allows the standby GET probe to finish before Play is
acknowledged. Position reads have a one-second cache. STOPPED/PAUSED_PLAYBACK
without a streaming response retains the last position; a new stream allows a
fresh read. A timeout overlapping a paused open request logs once per pause.
`SONOS_LMS_YENEY_STOPPED_MEDIAINFO=0` skips periodic GetMediaInfo while stopped or
paused; `1` restores those reads except while a paused request remains open.
Explicit currentUri reads are unaffected.

Title fallback substitutes the sent DIDL title for an empty title, stream URL or
basename with/without query. Real device titles remain visible. Volume uses
RenderingControl GetVolume, InstanceID 0 and Channel Master, cached for at least
one second. Failed transport polls mark the snapshot unavailable, never invent
STOPPED. Before retrying stream start, fresh transport/CurrentURI reads can
confirm the exact current stream is PLAYING/TRANSITIONING and avoid a repeat
SetAVTransportURI/Play. Other results retain the bounded three-attempt retry.

## Audio and lifecycle invariants

`upnp/encoded_buffer.*` owns 256 packet slots and signed little-endian sample
reading. Each write stores a whole packet and returns its length. An occupied
write slot is replaced without advancing the read cursor; if the read slot was
replaced, that packet is returned first. Tests pin this pre-removal behaviour,
including wrap-around, empty reads and clear while a reader holds a packet.
`bytesAvailable()` is the next packet size. Read packets survive clear until
freePacket. Operations are synchronized for a writer and reader. The first
overwrite per stream logs the capacity; reconnect encoders share that warning
history. PCM/FLAC settings and the capacity value remain unchanged.

HTTP EOF precedes Pause/Stop. ResumeState, the 25 ms GET-pair window, its 15-second
confirmation diagnostic, and connection-specific position anchoring remain
unchanged. EPIPE/ECONNRESET classification runs on a separate logging worker,
allowing two seconds for a matching pause/stop, response end or standby promotion.
Normal closes suppress the send-failure diagnostic; unexplained failures log once.
Socket cleanup does not wait for classification.

## Verification

`make test` covers XML/SSDP/topology, fixed SOAP bytes, loopback speakers, shared
HTTP/GENA serving, title and radio-text settings, packet storage, encoder output,
stream lifecycle, device trace replays and extracted production resume hooks.
XML rejects malformed trees, external entities, excessive depth and inputs over
2 MiB. HTTP supports numeric IPv4, bounded Content-Length/chunked/close-delimited
responses, and a single deadline without DNS or redirects.

Owner device evidence on 0a210f2: Study (Play:1) S2/S5/S6 and five S7 passes;
Sonos Port S1/S2/S5/S6/S7 passes; Study grouped under MBR S1/S7 passes. One S1
failure followed LMS dissolving a sync group with a Squeezebox Radio (strm q).
Physical acceptance remains owner-run; agents never SSH to or deploy on LXC 113.
